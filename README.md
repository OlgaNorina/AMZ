# a_maze_ing — учебный каркас проекта

Это **скелет**, а не готовое решение subject. В нём есть структура, базовые типы,
контракты функций, небольшие утилиты и TODO-комментарии. Генерацию, solver,
проверки ограничений и часть обработки конфигурации предстоит реализовать тебе.

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
cp config.example.txt config.txt
python3 -m src.main config.txt
```

Сейчас программа намеренно завершится сообщением о незавершённых TODO — это ожидаемо.

## Модель клетки и битовая маска

В каждой клетке `walls` — целое число от `0` до `15`.

| Бит | Направление | Маска |
|---|---|---:|
| 0 (LSB) | North | `1` |
| 1 | East | `2` |
| 2 | South | `4` |
| 3 | West | `8` |

`True`-стена означает закрытый проход. Например, `0xA` (`1010`) означает
закрытые East и West. Для удаления стены используй `walls &= ~MASK`,
для установки — `walls |= MASK`.

**Критически важно:** при открытии общей стены между соседними клетками нужно
изменить обе клетки: East у первой и West у второй (или соответствующую пару).

Координаты в проекте всегда `(x, y)`, доступ к сетке — `grid[y][x]`.
Ось Y направлена вниз: North уменьшает y, South увеличивает y.

## Предлагаемый порядок реализации

1. Прочитай `directions.py`, `cell.py`, `maze.py`; объясни себе, что хранится в каждой структуре.
2. Реализуй `Maze.remove_wall()` и `Maze.open_passage()` с проверками границ.
3. Реализуй `get_unvisited_neighbors()` и итеративный DFS в `generation/perfect.py`.
4. Реализуй `get_open_neighbors()` и BFS в `algorithms/solver.py`.
5. Реализуй валидатор: границы, симметрия стен, связность, entry/exit.
6. Добавь экспорт: строки hex, пустая строка, entry, exit, путь и завершающий `\n`.
7. Реализуй Pac-Man режим: сначала связная основа, затем добавление циклов, сохраняя остальные ограничения.
8. Реализуй 42 и проверку открытых областей. Тестируй каждое правило отдельно.

## Важные математические свойства

Рассматривай проходимую часть лабиринта как неориентированный граф:
- вершина — проходимая клетка (кроме зарезервированных клеток рисунка 42);
- ребро — открытый проход между соседними клетками;
- связность: все обычные клетки достижимы;
- для связного perfect maze: `E = V - 1`;
- число независимых циклов связного графа: `mu = E - V + 1`;
- BFS на невзвешенном графе находит кратчайший путь.

Для Pac-Man режима `mu >= 2`. Просто добавить случайные открытые стены недостаточно:
после каждого изменения проверяй ширину коридоров, связность и прочие ограничения.

## Конфигурация

`config.example.txt` показывает дополнительные ключи:
- `SEED`: целое число для воспроизводимости;
- `ALGORITHM`: `DFS` (пока предусмотрен только как планируемое значение);
- `DISPLAY`: `ASCII` или `NONE`.

`SEED` и остальные дополнительные параметры не заменяют требования subject.
Уточни в полном subject, как именно seed должен передаваться и какие значения
допустимы. Если способ не задан, согласуй формат с требованиями проекта.

## Что обязательно сверить с полным subject

В предоставленном фрагменте не полностью определены некоторые детали:
- точная геометрия и расположение рисунка `42`;
- точное определение «corridor wider than 2 cells»;
- допустимые минимальные размеры для рисунка, entry/exit, углов и центра;
- точный формат координат в выходном файле и требования к seed;
- считается ли клетка рисунка 42 исключением из всех проверок связности или только из проверки изолированных клеток.

Не угадывай эти правила: проверь полный subject и примеры evaluator. Каркас оставляет эти решения в отдельных модулях, чтобы их можно было менять без переписывания генератора.

## Стиль работы

Не заполняй сразу все TODO. Реализуй один модуль, напиши тесты, проверь крайние случаи,
и только потом переходи дальше. Старайся, чтобы генератор менял модель Maze, solver
только читал её, валидатор только проверял, а exporter только сериализовал.
